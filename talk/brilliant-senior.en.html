$ how you make one

A command and a subagent are both one markdown file.

.claude/commands/catchup.md

allowed-tools: Read, Glob, Bash(git log:*)
---

Read docs/STATE.md and the newest plan.
Report where we are, the next step,
and anything git contradicts.

Do not start work.
the filename is the command. the body is the prompt.
.claude/agents/explorer.md
---
name: explorer
description: Locates code and traces call
  paths. Use before making a change.
model: haiku
tools: Read, Grep, Glob
---

You locate code. You do not change it.
the description is what makes it get used.

That description is the whole trick for subagents.
Claude reads it to decide if a job is that agent's job.

$ /plan

The plan is the contract, and it lives in a file.

docs/plans/2026-08-edit-day-allocation.md
## Context          why, and what the user ends up seeing
## Files to touch   each path, one line on what changes there
## Interfaces       the actual types, quoted from the code
## Test cases       numbered, input and expected result
## Acceptance       the exact command that proves it
## Out of scope     and the reason for each

It has to be buildable by someone with no access to the conversation that produced it, so every decision made while exploring goes in the file rather than the chat.

That test section is how you get test-first. The expected results exist before any implementation does, so they cannot be derived from it.

$ four months of one project

Every turn sends the whole conversation again.

The model keeps nothing between messages. Turn fifty carries turns one to forty-nine along with it, and you pay to process all of them, again.

Over four months: 5.9 million tokens written, 1.64 billion processed.

Your limit goes on what it reads, not on what it writes.
